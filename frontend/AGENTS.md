# Frontend prototype agent instructions

This file covers the React/Vite **prototype**. Read [spec/00_README.md](../spec/00_README.md) and [spec/DECISIONS.md](../spec/DECISIONS.md) for product context, document authority and current decisions. The prototype is simulated; it does not prove a live Gateway, provider call, wallet transaction or Credit ledger.

## Working on the UI

- Run the local server and open the preview yourself when possible. Verify affected screens in the browser and run `npm run build` before handing off changes.
- Before substantial visual changes, use the Product Design plugin's context workflow **if available** when the visual source is unclear. When implementing a selected mock, follow its layout, spacing, typography, content and hierarchy.
- Keep the shared mobile header inside the viewport. Record durable prototype-specific design decisions here; keep product rules in their owning `spec/` documents.

## Current application layout

- The sidebar is **Chat, Studio, Credits, Tokenomics, Models, Providers, Referrals**. Models opens model pricing; Providers owns profiles and onboarding. Profile → Developer settings owns API keys and shows the linked wallet; Credits owns balances, subscription and Usage. Starters and Playground remain hidden.
- Tokenomics is one page with a shared position preview, guided entry (Mint & stake by default), guided exit (Unstake AIT & burn by default), individual actions, an interactive sample mint curve, Earn AIT and a compact illustrative MAX/AIT network dashboard instead of Activity, and a History section of the user's own transactions (TOK-R27–R28, TOK-R38, TD-71–73). MAX is locked to mint AIT and moves to pending redemption on burn; only AIT is staked. The mint review keeps the one-line unlock-risk statement. The combined paths are simulated; production may need separate wallet approvals and must leave minted AIT in the wallet if staking fails. Buy MAX/AIT buttons add sample tokens in the prototype without charging USDC; production CoW links require verified deployed token addresses (TOK-R37). Earn AIT links to the standalone `app.maxshot.ai/yields` portal (`[verify]` route, ACC-R10) for Vaults and partner referrals. An in-app aggregator swap is later scope.
- All four Tokenomics actions use one position preview beside the compact entry and exit controls. Show the relevant available balance beside each action amount: wallet MAX for mint, wallet AIT for stake, burnable AIT for burn and staked AIT for unstake. Position data appears only in the preview, with current → projected values after valid input and an empty state for a new account (TOK-R28, TD-73). Keep the mint curve visible in the preview for every action. Keep technical curve/HWM mechanics and general risk explanation in the spec, not the action table.
- Mint review takes a user-selected slippage tolerance and shows the derived maximum MAX input; it has no quote-expiry deadline (TOK-R10, R17, R28; TD-74). The prototype's 0.5% starting value is illustrative, not an approved launch default.
- Keep AIT Earned Credit status brief: Tokenomics shows the active term, eligible AIT × $12 per AIT-year → estimated Credits at the next seven-day boundary, with only period, expiry, rate and start/end in the term disclosure; a separate collapsed list holds recent 12 weeks of grants. Credits shows the spendable balance and next expiry in the top balance row beside Dollar balance, without grant history (TOK-R24, R27; TD-75–77). Posting follows chain finality; each grant expires seven days after issue. A projected grant is illustrative and never added to the Credit balance.
- Term acceptance never blocks Stake or Mint & stake. Before acceptance, the term card shows staked AIT, "Not earning yet", and one acceptance action; grant estimates and dates appear only after acceptance. The term summary reads "Active funded term", which is the funding status. During a term gap nothing pauses and one notice says no Credits accrue (TD-78/79/80).
- The sample position, its grant history, term acceptance and transaction history stay consistent when navigating between Tokenomics and Credits. The New sample has no prior grants; selecting another sample resets its local transaction history.
- The Gateway prototype has no Portfolio, Vault operations or partner referral page. Providers uses compact profiles and offering details, with onboarding behind one action and Provider Tokens in a later-phase disclosure.
- Referrals shows only **Maxshot Referrals Program**. The Gateway example measures confirmed Dollar-balance top-ups in USD and displays promotional Credit rewards separately; its rate and conversion are illustrative.
- The standalone AIT Earn placement and removal of Portfolio are governed by TD-68/69 and [SPEC_ACCOUNT_VAULT](../spec/SPEC_ACCOUNT_VAULT.md).

## Providers, model choice and pricing

- Use `src/data/providerCatalog.js` as the single simulated `providerSnapshot` for Providers, Models & Pricing, Chat and Studio. Derive model identity, display name, Chat eligibility and usable picker membership from it. A new-request picker shows only admitted, available, policy-eligible models; keep at least five distinct usable sample models each for text, image and video. Historical records may retain unavailable model names, but retrying an old creation must switch to a usable model with notice.
- Providers owns profiles, offering admission and availability, per-offering capabilities/limits/data policy, and only the agreed customer-facing observed measures: delivered success and p50/p95 latency with window and sample count. Show **Insufficient data** when the sample is too small. Keep provider cost, metering completeness and invoice reconciliation internal. Do not add a duplicate request-routing simulator or public ranking.
- TD-54 prototype changes (done 16 November 2026): Chat and Studio have a **Provider** selector (Auto default; a pin shows "Pinned · no fallback" in the quote and Usage, TD-48); Developer settings keys carry allowed catalogs, per-request ceiling, daily/monthly budget, Dollar-spend toggle and expiry (TD-44); Usage and the API request log show request IDs, Usage filters by request ID and API key, Pending rows show the held amount (TD-46/49). `src/data/launchConfig.js` mirrors [LAUNCH_CONFIG_V0](../spec/LAUNCH_CONFIG_V0.md); read values from it rather than hard-coding. `PricingPage.jsx` renders the Models portal; Playground and Starters stay unreachable from navigation.
- Models compares each admitted provider-model offering's **own complete customer rate card** for an exact model/version. Do not assume equivalent providers have equal rates or combine components from different offerings into a model price. Credits and provider profiles may link to this view.

## Credits and request examples

- Use **Dollar balance** for funded USD and **AIT Earned Credit** for the staking-derived off-chain allowance. Subscription Basic-chat/Premium allowances, Free Credits and Referral Credits are separate buckets. Follow the [SPEC_BILLING](../spec/SPEC_BILLING.md) for authorization, funding and settlement behavior.
- Keep the quote walkthrough explicitly simulated. Chat and Studio show selected offering/rate, estimate, hard maximum and illustrative hold before submission. The mock Claude Chat completion creates a matching Credits → Usage example with one same-model fallback, verified units, one final charge and released hold. Credits use the live unit `1,000,000 Credits = $1` from `src/data/launchConfig.js` (TD-53). Rates, units and the AIT/Premium hold split in `src/data/sampleRequest.js` are illustrative; they do not debit balances or define a funded term.
- MAX/AIT actions in `src/pages/TokenomicsPage.jsx` mutate browser sample state. Do not use its floating-point mint quote as contract arithmetic; use the [integer quote vectors](../spec/SPEC_TOKEN.md#3-confirmed-integer-mint-quote) for production work.
